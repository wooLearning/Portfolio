1. Project Goal: Little MCU Design

직접 만든 RV32I core로 동작 가능한 작은 MCU SoC 설계

Little MCU 구성

CPU 하나만이 아니라 MCU처럼 동작하는 최소 시스템을 구성합니다.

  • Custom RV32I Core
  • Instruction ROM / SRAM
  • Memory-mapped peripheral

3.2 AXI-Lite Fabric & APB Bridge

단일 Master 구조

Core DBus ➔ AXI-Lite Master Adapter를 거쳐 하나의 Master로 진입합니다.

AxiLiteInterconnect1x3

Address Decoder가 주소를 판별하고, Demux/Mux를 통해 ROM, SRAM, APB Bridge 3개의 Slave로 라우팅합니다.

APB Subsystem 통합

AxiLiteToApbBridge를 거친 PADDR, PWDATA 등의 신호는 다시 APB Address Decoder를 통해 각 Peripheral 칩셋을 구동합니다.

4.1 AXI-Lite vs AXI-Stream

AXI-Lite

역할 CPU가 peripheral register를 읽고 쓰는 control path
주소 존재함. 접근할 타겟 레지스터의 주소 공간 지정
신호 5채널 (AW, W, B, AR, R) 기반의 독립적 트랜잭션
적용 CPU의 DMA, UART, SPI, PLIC 레지스터 설정 및 상태 폴링

AXI-Stream

역할 byte payload가 흐르는 data path
주소 없음. Valid/Ready 핸드셰이크에 의한 순차적 데이터 흐름
신호 TVALID, TREADY, TDATA 중심의 단방향 전송
적용 UART RX ➔ DMA 내부 버퍼 ➔ SPI TX 간의 대규모 페이로드 이동
핵심 설계: AXI-Lite 기반 메모리 맵 제어와 AXI-Stream 기반 대용량 데이터 전송 경로의 분리

4.2 AXI Path Summary

5.1 RV32 Pipeline Core

5-Stage Pipeline 구조

  • IF/ID/EX/MEM/WB: 전형적인 RISC 5단계 파이프라인.
  • Forwarding Unit: 데이터 해저드 완화를 위한 FWD A/B 바이패스 제공.

Trap & CSR

  • Trap Controller: PLIC/Timer에서 온 외부 IRQ와 예외를 처리.
  • CSR File: mepc, mcause 상태 기록 및 분기 제어.

Pipeline 제어 포인트

  • Hazard / Forward: load-use, branch, data hazard를 stall/flush/forwarding으로 제어.
  • Fast Path: IBus는 IcodeLocalRom으로 분리하고, payload 이동은 DMA로 offload.

5.2 Peripheral Architecture

APB Slave Interface

모든 주변장치는 표준화된 APB 노드를 통해 연결되며, 일관된 CSR(Control/Status Register) 인터페이스를 제공합니다.

Peripheral 내부 블록

  • UART: TX/RX Shift Register 및 오버샘플러
  • SPI: SCK 생성 및 MOSI/MISO Shift 구동
  • I2C: SCL 타이밍 및 Start/Stop/Ack 제어

IO 패드 매핑

컨트롤러의 최종 입출력은 동기화 회로(Synchronizer)를 거쳐 물리적 IO Pad Buffer와 안전하게 연결됩니다.

5.3 PLIC (Platform-Level Interrupt Controller)

IRQ Source & Gateway

UART/SPI/DMA에서 발생한 raw IRQ는 Gateway를 거쳐 request pulse가 되고, complete 전까지 중복 요청을 막습니다.

Pending / Enable / Priority

pending source 중 enable되어 있고 threshold보다 priority가 높은 항목만 CPU가 claim할 수 있는 후보가 됩니다.

Arbiter & Claim/Complete

Arbiter가 priority가 가장 높은 source ID를 고르면 external IRQ가 올라갑니다. CPU는 CLAIM으로 ID를 읽고, 처리 후 COMPLETE에 같은 ID를 써서 정리합니다.

5.4 Interrupt Path & CSR

인터럽트 발생 구조

1

하드웨어 인터럽트 이벤트 발생 (예: DMA 전송 완료)

2

PLIC에서 우선순위를 판별하여 Machine External Interrupt (MEIP) Assert

3

Trap Controller가 실행 흐름을 멈추고 CSR (mepc, mcause) 하드웨어 업데이트

4

프로그램 카운터(PC)가 mtvec=0x80 Direct Trap Entry 진입

관여하는 핵심 CSR

CSR 역할 설명
mtvec Trap entry base (이번 firmware image는 0x80)
mie.MEIE Machine external interrupt enable
mstatus.MIE Global machine interrupt enable
mcause Interrupt 여부와 원인 기록
mepc Trap 발생 전 PC 저장

5.5 Software Vector Table (vs ARM NVIC)

최종 interrupt routine은 둘 다 ROM/Flash의 code 영역에 있습니다. 차이는 ARM NVIC는 하드웨어가 vector table에서 handler 주소를 직접 읽어 PC를 옮기고, 본 설계는 mtvec direct 진입 후 software가 PLIC Claim ID로 handler를 고른다는 점입니다.

비교 항목 ARM NVIC 현재 RISC-V firmware 설계
Table Lookup 주체 Hardware Software
Entry 방식 IRQ number ➔ Vector entry 이동 mtvec=0x80 Direct Trap으로 통합 진입
Source 구분 IRQ number PLIC Claim ID
Handler 분기 Hardware가 Handler PC Load Software가 Table Load 후 jalr 분기
Routine 위치 Flash/ROM의 ISR code ROM image의 trap/handler code

5.6 PLIC-lite Claim/Complete Flow

1. Raw IRQ Sources
UART/SPI/DMA interrupt level 입력
↓
2. Gateway
1-cycle request pulse 생성, complete 전 중복 request 차단
↓

↓
4. External IRQ to Core
claim 후보 존재 시 oExternalIrq가 올라가고 core는 external interrupt trap 진입
↓
5. Software Claim/Complete
handler가 CLAIM ID를 읽고, 처리 후 COMPLETE에 같은 ID를 write

PLIC의 역할

handler 주소 대신 CPU에게 interrupt source ID를 알려줍니다.

Data Payload Movement

RGB payload는 CPU register나 SRAM을 거치면서 한 byte씩 복사하지 않고, 오직 DMA internal buffer와 Stream handshake로 통신합니다.

  • UART RX Stream ➔ DMA Internal Buffer (16 KB) ➔ SPI TX Stream
  • RGB888 64x64 프레임(12,288 bytes)을 한 번에 담을 수 있는 버퍼 크기.

7.4 Result & Lessons Learned

Project Results

  • AHB 기반 참고 구조에서 AXI-Lite/APB/AXI-Stream 구조로 성공적 전환
  • RV32I core + AXI-Lite fabric + APB subsystem + AXI-Stream DMA 통합 구성
  • PLIC claim ID 기반 Software vector table dispatch 구현 및 IRQ phase 제어 증명

"처음 STM32F103 데이터시트를 봤을 때는 전체 구조가 잘 보이지 않아 막막했지만, core, bus, peripheral을 하나씩 공부하고 직접 구성하면서 데이터시트의 블록들이 어떤 역할로 연결되는지 조금씩 보이기 시작했습니다."

"Interrupt 처리에서 ARM NVIC처럼 hardware가 바로 vector table을 찾아가는 방식과, RISC-V에서 mtvec, PLIC claim, software dispatch를 직접 구성하는 방식의 근본적 차이를 체감했습니다."

"Linker, compiler, loader까지 직접 설계하기에는 범위가 컸고, 이번에는 assembly를 ROM image로 직접 올리는 방식으로 진행했습니다. 그만큼 bitstream을 다시 만들어야 하는 흐름의 불편함도 체감했습니다."
